CHAPTER 017 MIN · DISCUSSION

One app. Every step to the cloud.

Today we will turn a Python application into a running, observable service. Our example is Humanizer: a draft goes in, a reviewed rewrite comes out.

What you will be able to do

  • Explain what happened inside one AI request, including model calls, latency, and failures.
  • Build a Docker image and create, start, inspect, stop, and remove a container.
  • Deploy the same repository to Railway and verify it from a public URL.
  • Map the same image to Azure Container Apps and AWS ECS on Fargate.

The application

Browser → POST /humanize → LangGraph → rewrite → evaluate → repeat if needed → JSON response.

The graph exits at the configured score threshold or pass limit. Each live pass normally makes two model calls.

The evidence

A request ID joins the browser, JSON logs, and the root LangSmith trace. Child runs reveal where time and model usage went.

LangSmith observes the application; Docker packages it; Railway runs it.

Three words students often mix up

Logs are timestamped events such as “request completed.” Metrics summarize many events: request count, error rate, p95 latency. Traces show the sequence and nesting of operations for one request. A span is one operation inside that trace.

p95 latency means 95% of the measured requests completed at or below that duration. A single slow trace is a clue, not a p95 measurement.

Instructor opening

“The answer looks good. But which model calls produced it, how long did they take, and can we run this on another machine?”

3. Walk students through the trace

  1. Find the project. In Tracing, select deployments-observability. Open the newest humanize.request, or click Inspect trace in the app.
  2. Correlate it. Match its root run ID to the request ID shown in the app and JSON server logs.
  3. Expand the tree. Open humanizer.graph, then rewrite and evaluate. Expand further to inspect the model calls. Evaluator output parsing may add extra spans.
  4. Read the prompt and response. Locate the editor’s system instructions, the draft, and the evaluator’s structured score and feedback.
  5. Explain the loop. If the score is below the threshold, another rewrite follows. Reaching the pass cap can return a lower score.
  6. Inspect latency and usage. Compare writer versus evaluator durations. Inspect input/output tokens on the LLM child runs. Supported model pricing enables LangSmith cost estimates; missing cost is not proof the call was free.
  7. Filter the evidence. Use the live, demo, local, docker, or railway tags and metadata to separate environments.

Where is the instrumentation in the code?

app/telemetry.py creates a configured LangSmith client and counts provider-reported tokens. app/api/routes.py creates the root span and sets tags, metadata, inputs, and outputs. LangChain/LangGraph create child spans automatically inside that tracing context. app/agent/workflow.py also measures step durations for the UI. app/logging_conf.py emits correlated JSON events to stdout.

Privacy and interpretation

Use fictional text for class. Tracing can send prompts, model outputs, metadata, and errors to LangSmith. Set LANGSMITH_HIDE_INPUTS=true and LANGSMITH_HIDE_OUTPUTS=true to hide ordinary payloads; this does not automatically redact every error string or metadata value. Restart after changes.

The review score is a model judgment about writing, not an AI detector, a factuality guarantee, or a human rating. Tracing tells us what happened; evaluation is a separate process for judging quality. Do not compare synthetic demo scores to real model scores.

CHAPTER 0415 MIN · HANDS ON

The Dockerfile is a recipe.

An image packages the Python runtime, dependencies, and application files. A container is an instance created from that image.

01

Dockerfile

The build instructions.

02

Image

The built, reusable artifact.

03

Container

An isolated instance with runtime configuration and a writable layer.

1. Read the project’s Dockerfile

The file has no extension and lives at the repository root. This is the exact classroom Dockerfile; students can recreate it from the block below.

Dockerfile · exact project contents
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PORT=8000

WORKDIR /app

RUN addgroup --system app && adduser --system --ingroup app app

COPY requirements.lock ./
RUN pip install --no-cache-dir -r requirements.lock

COPY --chown=app:app app ./app

USER app
EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:' + __import__('os').environ.get('PORT', '8000') + '/health', timeout=2)"

CMD ["python", "-m", "app.main"]
InstructionExplain it like this
FROMStart with Python already installed on a small Linux base.
ENVSet harmless defaults. Never bake credentials into an image.
WORKDIRChoose the directory for later build and runtime commands.
RUNExecute during the image build, such as installing dependencies.
COPYCopy selected files from the build context into the image.
USERRun the web process as a non-root user.
EXPOSEDocument the intended port. It does not publish a host port.
HEALTHCHECKTell Docker how to probe the process after it starts.
CMDChoose the command to execute when a container starts.

Explain the command

-t gives the image a name and tag. The final . makes the current directory the build context. Building an image does not start the app.

4. Show layer caching

Run the same build again and look for cached steps. Change a heading in app/static/index.html and rebuild with tag 1.1. The dependency install can remain cached because requirements were copied before application code.

Terminal
docker build -t humanizer-lab:1.1 .
What does “the same image everywhere” really mean?

The same application packaging can run across platforms that support its CPU architecture and container OS. A Mac’s ARM image is not automatically an x86 image. Railway builds in its own environment. For a manual cloud image build from Apple Silicon, specify the target architecture (often linux/amd64) or publish a multi-platform image. Configuration and secrets are injected separately at runtime.

CHAPTER 0512 MIN · HANDS ON

An image becomes a running service.

Keep the local Python app on port 8010. Publish the container on port 8011 so students can compare them side by side.

1. Create, then start

Use the .env you already configured. The command overrides the internal port to 8000 and tags traces as docker.

Terminal
docker create --name humanizer-class --env-file .env -e PORT=8000 -e ENVIRONMENT=docker -p 127.0.0.1:8011:8000 humanizer-lab:1.0
docker ps -a
docker start humanizer-class
docker ps
Pause before starting

docker create makes a stopped container. docker start runs it. docker run combines those two steps.

2. Open and verify

Open localhost:8011 and submit the sample. The interface and behavior should match your local app.

Terminal
curl http://localhost:8011/health
docker logs --tail 30 humanizer-class
docker inspect --format '{{.State.Health.Status}}' humanizer-class
docker exec humanizer-class id
python scripts/smoke.py --url http://localhost:8011 --verify-trace

Health may initially be starting; allow a probe interval before expecting healthy. The id command should show the app user, not root. Find the new trace’s docker tag.

Browserlocalhost:8011→Docker port mapping→container:8000

The left port belongs to your computer. The right port is where Python listens inside the container. Binding the host mapping to 127.0.0.1 keeps this local classroom instance on your machine.

3. Stop, restart, and remove

Terminal
docker stop humanizer-class
docker ps -a
docker start humanizer-class
docker stop humanizer-class
docker rm humanizer-class

Stopping preserves the container; removing deletes that container’s writable layer. The image still exists. This app is stateless and does not persist drafts.

4. Use the shorter run command

Terminal
docker run -d --name humanizer-class --env-file .env -e PORT=8000 -e ENVIRONMENT=docker -p 127.0.0.1:8011:8000 humanizer-lab:1.0

Optional: Compose is the repeatable version

Stop the named container first so Compose can use the same host port.

Terminal
docker stop humanizer-class
docker compose up --build -d
docker compose ps
docker compose logs --tail 30
docker compose down
Common gotcha

Changing .env does not update an existing container. Recreate it. Changing code requires rebuilding the image and creating a container from the new image. docker restart does neither.

Checkpoint question

If you remove a container, do you lose the image? No. They are separate objects. One image can create many containers, each with its own lifecycle and runtime configuration.

Deployment walkthrough

  1. Choose a subscription and region. Put classroom resources in a dedicated resource group so cleanup is easy to identify. Confirm the subscription’s budget before provisioning.
  2. Create Azure Container Registry (ACR). Build and push a Linux image using ACR’s remote build, or Docker with the target platform.
  3. Create a Container Apps environment and app. Point the app at your ACR image/tag. Grant its managed identity permission to pull that image rather than distributing registry passwords.
  4. Set ingress. Enable external HTTP ingress and set the target port to 8000. Set runtime PORT=8000 and ENVIRONMENT=azure.
  5. Add configuration and secrets. Add LangSmith variables and the mode. Store API keys as Container Apps secrets or Key Vault references; reference them from environment variables. Managed identity needs the appropriate Key Vault permissions.
  6. Define probes and scaling. Use /health for liveness/startup and /ready for configuration readiness. Discuss minimum replicas, cold starts, and maximum replicas.
  7. Verify and inspect. Open the app’s HTTPS address, send a request, inspect console logs, then locate the azure trace in LangSmith.

Deployment walkthrough

  1. Create a private ECR repository. Authenticate Docker, tag the image with the repository URI, and push it.
  2. Create an ECS cluster and Fargate task definition. Set a compatible Linux CPU architecture, CPU/memory, the ECR image URI, and container port 8000.
  3. Separate IAM roles. The task execution role allows image pulls, log delivery, and reading injected secrets. A task role is for AWS API access made by your running application; this app does not need broad AWS permissions.
  4. Add runtime variables. Set PORT=8000, ENVIRONMENT=aws, app mode, and LangSmith settings. Reference Secrets Manager or Parameter Store entries for credentials.
  5. Create a service. Choose VPC subnets, security groups, and a load balancer. Route the load balancer to container port 8000; use HTTPS with a certificate for a public deployment.
  6. Allow outbound access. The app needs HTTPS access to OpenAI and LangSmith. Private tasks usually require a NAT route for these public APIs. ECR and secrets access also require suitable routes or VPC endpoints.
  7. Define health checks explicitly. Set the load balancer check to /health. If using ECS container health checks, add them to the task definition; ECS does not simply monitor the Dockerfile’s health check.
  8. Verify. Inspect service events and CloudWatch logs, send a request, then find its aws LangSmith trace.

CHAPTER 100 MIN · DISCUSSION

When the demo does not behave.

Use the symptom to choose the next piece of evidence. Avoid changing five things at once.

SymptomCheck next
Port already in useAnother process owns the host port. Keep it running if unrelated. Choose another local PORT, or change only the left side of Docker’s -p mapping.
Cannot connect to Docker daemonStart Docker Desktop and wait until docker info succeeds.
